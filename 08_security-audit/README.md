# 08_security-audit -- セキュリティ脆弱性の検出と自動修正

所要時間: 約20分

## テーマ

認証機能を持つExpressアプリケーションのソースコードを読み、セキュリティ脆弱性を洗い出す。
人間による目視レビューでは見落としがちな脆弱性を、AIがどこまで網羅的に検出できるか体験する。

## 題材

架空の認証APIサーバ。Express + TypeScript + better-sqlite3 で構成された5ファイル、約200行。
意図的に10個のセキュリティ脆弱性を埋め込んである。すべてOWASP Top 10やCWEに対応する現実的な問題で、教育目的で配置したもの。

注意: コード中のAPIキーや秘密鍵はすべてデモ用のダミー値。本物の機密情報は一切含まれていない。

## フォルダ構成

```
08_security-audit/
  input/
    auth-app/
      server.ts          -- Expressサーバのエントリポイント
      auth.ts            -- ログイン・JWT発行
      users.ts           -- ユーザー登録・取得
      middleware.ts       -- 認証・セキュリティ系ミドルウェア
      db.ts              -- SQLiteデータベース初期化
  before/
    audit-report.md      -- 人手で作成した監査レポート（10件中6件検出）
  with-ai/
    prompt.md            -- Claude Codeに渡すプロンプトテンプレート
  expected-output/
    audit-report.md      -- AI生成の完全版監査レポート（10件全件検出）
    fixed/
      server.ts          -- 修正済みサーバ
      auth.ts            -- 修正済み認証
      users.ts           -- 修正済みユーザー管理
      middleware.ts       -- 修正済みミドルウェア
      db.ts              -- 修正済みデータベース
```

## Before / After 比較

before/ の監査レポートには以下の限界がある。

- 10件中6件しか検出できていない
- SQLインジェクションやCORS設定の不備など、目につきやすい問題は見つけている
- 平文パスワード保存、エラーメッセージでの機密情報漏洩、CSRF未対策、ファイルパーミッション不備の4件を見落としている
- OWASPやCWEとの対応付けが不完全で、組織としてのリスク評価に使いにくい

expected-output/ では10件すべてを検出し、CWE番号・OWASP分類・重大度・修正コード付きで報告している。
fixed/ ディレクトリには、全脆弱性を修正した5ファイルが格納されている。

## 埋め込み済み脆弱性一覧

| # | ファイル | 脆弱性 | CWE |
|---|----------|--------|-----|
| V1 | server.ts | CORSを全ドメイン許可（"*"） | CWE-942 |
| V2 | server.ts | ログインエンドポイントにレート制限なし | CWE-307 |
| V3 | auth.ts | SQLインジェクション（文字列結合） | CWE-89 |
| V4 | auth.ts | パスワードを平文保存 | CWE-256 |
| V5 | auth.ts | JWTシークレットをハードコード | CWE-798 |
| V6 | users.ts | ユーザー作成時の入力バリデーションなし | CWE-20 |
| V7 | users.ts | エラーメッセージに機密情報を含む | CWE-209 |
| V8 | middleware.ts | CSRF対策なし | CWE-352 |
| V9 | middleware.ts | HTTPSリダイレクト・セキュリティヘッダなし | CWE-319 |
| V10 | db.ts | DBファイルが全ユーザー読み書き可能 | CWE-732 |

## デモ手順

1. input/auth-app/ の5ファイルを開き、アプリケーションの全体像を把握する（3分）
2. before/audit-report.md を開き、人手でのセキュリティ監査結果を確認する（3分）
3. 見落とされた脆弱性がどこにあるか、受講者に考えてもらう（3分）
4. with-ai/prompt.md のプロンプトを使い、Claude Codeで監査レポートを生成する（5分）
5. expected-output/ と比較しながら、AIが検出した追加の脆弱性と修正内容を解説する（6分）

## 学びのポイント

- 人間のコードレビューは目立つ問題（SQLインジェクション等）に引っ張られ、地味だが危険な問題を見落としやすい
- AIは既知の脆弱性パターンを網羅的に走査するため、チェックリストの抜け漏れが起きにくい
- CWEやOWASPとの対応付けを自動で行えるのは、セキュリティ専門知識が少ないチームにとって大きな助けになる
- 修正コードの自動生成まで一気通貫で行える点が、従来のSASTツールとの差別化になる
- 一方で、ビジネスロジック固有の脆弱性やアーキテクチャレベルの設計問題は、AIだけでは判断しきれない
