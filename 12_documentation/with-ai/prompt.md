# ドキュメント自動生成プロンプト

以下のプロンプトをClaude Codeに投入する。
input/src/ ディレクトリのコードを読み取り、5種類のドキュメントを一括生成する。

---

## プロンプト

```
input/src/ 以下のTypeScriptコードを全ファイル読み込み、以下の5種類のドキュメントを日本語で生成してください。
出力先は output/ ディレクトリです。

生成対象:

1. output/README.md -- プロジェクトREADME
   - このAPIが何をするものか、コードの実装内容から推測して概要を書く
   - 使用技術スタック（package.jsonがなくてもimport文から判断すること）
   - ローカル環境でのセットアップ手順（clone, install, env設定, migrate, 起動）
   - ディレクトリ構成と各ファイルの責務（1ファイル2-3行で説明）
   - 関連ドキュメントへのリンク

2. output/api-reference.md -- API仕様書
   - エンドポイント一覧表（メソッド、パス、説明、認証要否、必要ロール）
   - 認証方式の説明（JWTの使い方、トークン有効期限、リフレッシュフロー）
   - レート制限の仕様
   - 各エンドポイントの詳細:
     * リクエストボディのJSON例（Zodスキーマから正確に読み取ること）
     * バリデーションルール（最小/最大文字数、型、必須/任意を明記）
     * レスポンスボディのJSON例（includeやselectから構造を推測）
     * 想定されるエラーとHTTPステータスコード
   - エラーレスポンスの共通形式
   - エラーコード一覧（コード上のcodeフィールドから収集）
   - HTTPステータスコード一覧と発生条件

3. output/architecture.md -- アーキテクチャ概要
   - アーキテクチャの概要説明
   - Mermaidによるコンポーネント構成図（server, routes, middleware, db, utils間の依存関係）
   - Mermaidによるリクエスト処理フロー図（レート制限→認証→ロール制御→バリデーション→ハンドラの順序）
   - Mermaidによる注文ステータス遷移図（STATUS_TRANSITIONSオブジェクトから正確に読み取る）
   - 注文作成の処理フロー図（在庫チェック→クーポン→税計算→送料→トランザクションの流れ）
   - レイヤー間の責務の説明

4. output/env-vars.md -- 環境変数リファレンス
   - コード中の process.env.XXX を全て収集した一覧表（変数名、必須/任意、デフォルト値、説明）
   - 各変数の詳細説明（参照箇所、挙動への影響）
   - .envファイルのテンプレート（全変数を含み、値はダミー）
   - シークレット生成用のコマンド例

5. output/deploy-guide.md -- デプロイガイド
   - 前提条件（Node.jsバージョン、必要なサービス）
   - ローカルビルドと実行の手順（install, prisma generate, migrate, tsc, 起動）
   - マルチステージビルドのDockerfileサンプル（非rootユーザー、ヘルスチェック付き）
   - docker-compose.ymlサンプル（API + PostgreSQL、全環境変数を含む）
   - ヘルスチェックの確認方法
   - 本番環境のチェックリスト

制約:
- 全て日本語で記述する
- 絵文字は一切使わない
- コードに書かれていない情報を推測で補う場合は「推定」と明記する
- 環境変数のサンプル値には本物のシークレットを使わない
- Mermaid図はGitHubで描画可能な構文にする
- ページネーションのレスポンス形式はコードのres.json()呼び出しから正確に読み取る
- ロールベースのアクセス制御の有無はrequireRole()の引数から判定する
- バリデーションルールはZodスキーマの定義から正確に転記する（min, max, optional等）
```

---

## 使い方

1. このリポジトリのルートで Claude Code を起動する
2. 上記プロンプトをそのまま貼り付ける
3. 生成された output/ 以下のファイルを確認する
4. expected-output/ と比較して精度を評価する

## 評価観点

- エンドポイントの網羅性（20エンドポイント全て記載されているか）
- 型定義の正確性（Zodスキーマの各制約が反映されているか）
- ステータス遷移の正確性（STATUS_TRANSITIONSと一致しているか）
- 環境変数の網羅性（process.env参照を全て拾えているか。11変数）
- 認証要否の正確性（authenticateミドルウェアの有無と一致しているか）
- ロール制御の正確性（requireRoleの引数と一致しているか）
- レスポンス構造の正確性（metaフィールドのtotalPages等が含まれるか）
- エラーコードの網羅性（code付きエラーが全て列挙されているか）
- 注文作成フローの正確性（税計算、送料計算、クーポン適用の順序）
