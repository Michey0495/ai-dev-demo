# 01_requirements -- 会議議事録からの要件定義

## テーマ

キックオフ会議の議事録を読み、構造化された要件定義書を作成する。
人間が手作業で行うと抜け漏れが発生しやすい工程を、AIがどこまで補完できるかを体験する。

## Before / After 比較

### Before（人手で作成）

- 会議で明示的に発言された機能要件のみを拾っている
- 途中参加者（情シス）の要件が丸ごと漏れている
- 非機能要件（性能、セキュリティ、可用性、法規制）が欠落
- 暗黙の要件（会話の文脈から読み取れるもの）を見落としている
- 予算制約や部門間対立がドキュメントに反映されていない
- 優先度の設定がない
- ユーザーストーリー形式になっていない
- フォーマットに統一感がない（箇条書きとナンバリングが混在）

所要時間の目安: 30-45分

### After（AI活用）

- 機能要件と非機能要件を網羅的に抽出（法規制含む）
- 会話の行間から暗黙の要件を推論（10件以上）
- 部署間の利害衝突を [係争] タグで可視化
- MoSCoW法による優先度分類（予算・納期制約を加味）
- ユーザーストーリー形式での整理（5ロール、20件超）
- 要件間の依存関係・矛盾点の指摘
- 組織的リスクとブロッカーの識別

所要時間の目安: 3-5分（プロンプト作成・確認含む）

## ファイル構成

```
01_requirements/
  input/
    meeting-minutes.md        ... キックオフ会議の議事録（架空）
  before/
    requirements.md           ... 人手で作成した要件定義（意図的に不完全）
  with-ai/
    prompt.md                 ... Claude Codeに渡すプロンプトテンプレート
  expected-output/
    requirements.md           ... AIが生成する完全な要件定義の見本
```

## デモ手順

1. input/meeting-minutes.md を開いて内容を把握する（2分）
2. before/requirements.md を見せて、人手で作った場合の限界を説明する（2分）
3. with-ai/prompt.md のプロンプトを Claude Code に貼り付けて実行する（1分）
4. 生成結果と expected-output/requirements.md を比較し、差分を議論する（5分）
5. before との差分から、AIが補完した暗黙の要件を確認する（5分）

## 学びのポイント

会議中の雑談や脱線に埋もれた要件をAIは拾える。「在庫が100万件超えるかも」という一言からスケーラビリティ要件を導出したり、「前のシステムは起動に30秒かかった」という愚痴からパフォーマンス目標値を定義する。途中参加者が持ち込んだ全社セキュリティポリシーのような、既出要件と矛盾する情報も見逃さない。部署間の対立（情シスのVPN制限 vs 営業の外出先利用）を設計上のトレードオフとして構造化できるのもAIの強み。ただしAIの出力は出発点であり、ドメイン知識を持つ人間のレビューは不可欠。
