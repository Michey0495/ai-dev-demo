# ECサイト データ要件

オンラインで雑貨を販売する小規模ECサイトを新規構築する。
以下は、事業部門から寄せられたデータに関する要望をまとめたものである。


## ユーザー情報

会員登録にはメールアドレスとパスワードが必須。
同じメールアドレスでの二重登録は許可しない。
氏名（姓・名）と電話番号も登録時に入力してもらう。電話番号は任意項目。
配送先住所は郵便番号・都道府県・市区町村・番地の4つに分けて管理したい。
会員のステータスとして「有効」「停止」「退会済み」の3種類を設ける。
登録日時と最終更新日時を記録しておくこと。


## 商品情報

商品には商品名、説明文、税抜価格、在庫数を持たせる。
価格は0円以上の整数。在庫数もマイナスにはならない。
商品ごとにSKUコード（在庫管理用の一意な英数字コード）を付与する。
各商品は必ず1つのカテゴリに所属する。
公開中・非公開・販売終了の3つの販売ステータスを持つ。
登録日時と最終更新日時も必要。


## カテゴリ情報

カテゴリは「キッチン」「インテリア」「ステーショナリー」のように商品を分類するためのもの。
カテゴリ名は重複不可。
今後カテゴリが増える可能性があるため、柔軟に追加できる設計にしたい。
表示順を制御するための並び順フィールドがほしい。


## 注文情報

会員が商品を購入すると注文が作成される。
注文には一意の注文番号を発行する。注文番号は「ORD-20260324-0001」のような書式。
注文ごとに合計金額（税込）を保持する。
注文ステータスは「未決済」「決済済み」「発送準備中」「発送済み」「キャンセル」の5種類。
配送先は注文時点の住所を注文データ側に保存する（会員が後から住所変更しても注文時の住所が残るように）。
注文日時を記録する。


## 注文明細

1つの注文に複数の商品が含まれることがある。
明細ごとに、どの商品を何個注文したか、注文時点の単価はいくらかを記録する。
単価 x 数量 で小計が算出できるようにしたい。
