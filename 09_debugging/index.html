diagnosis.md -- AI診断（5分）

原因特定+修正済
1. ログ全件分類
条件 件数 エラー
割引なし6件0
ポイントのみ7件0
クーポンのみ5件0
ポイント+クーポン併用6件6
併用注文のエラー率100%。ポイント単独・クーポン単独では1件もエラーなし。9月以前に併用注文は存在しなかった。バグは税率変更が原因ではなく、以前から潜伏していた。
2. 差額の法則性
注文ID ポイント クーポン率 P*r 差額
1001-0043000.206060
1001-0075000.105050
1001-01010000.20200200
1001-0132000.102020
1001-0166000.20120120
1002-0014000.208080
全件で 差額 = ポイント利用額 x クーポン割引率 が成立。偶然ではない。
3. 数式による証明
// 変数定義
T = 税込金額, P = ポイント利用額, r = クーポン割引率
// calculateTotal（バグあり）
最終金額 = (T - P)(1 - r)
// verifyAmount（仕様準拠）
最終金額 = T(1 - r) - P
// 差額
(T-P)(1-r) - (T(1-r) - P)
= T - P - Tr + Pr - T + Tr + P
= P * r
4. 根本原因
order-service.ts 50行目。calculateCouponDiscount に渡す引数が afterPoints（ポイント差引後）になっている。仕様では totalWithTax（税込金額全体）が正しい。

同じ関数を呼んでいるため、関数自体にバグはない。引数が1つ違うだけ。applyAllDiscounts という仕様準拠の一括関数が存在するが、calculateTotal はこれを使わず個別に組み合わせている。
5. 修正コード（推奨案）
order-service.ts -- calculateTotal
function calculateTotal(subtotal: number, order: Order): OrderResult {
  const taxRate = getTaxRate(order.orderDate)
  const taxAmount = calculateTax(subtotal, taxRate)
  const totalWithTax = subtotal + taxAmount

  const { couponDiscount, pointDiscount, finalAmount } = applyAllDiscounts(
    totalWithTax, order.pointsUsed, order.coupon
  )

  return {
    orderId: order.orderId,
    subtotal, taxAmount, totalWithTax,
    pointDiscount, couponDiscount, finalAmount,
  }
}

// 注文処理サービス
// 注文の受付から金額計算・保存・通知までを統括する

import { Order, OrderResult } from './types'
import { getTaxRate, calculateTax } from './tax-calculator'
import {
  calculatePointDiscount,
  calculateCouponDiscount,
  applyAllDiscounts,
} from './discount-service'
import { saveOrder } from './order-repository'
import { sendOrderConfirmation } from './notification-service'
import { AMOUNT_TOLERANCE } from './config'

// 注文を処理する
export async function processOrder(order: Order): Promise<OrderResult> {
  // 商品合計（税抜）を算出
  const subtotal = order.items.reduce(
    (sum, item) => sum + item.unitPrice * item.quantity, 0
  )

  const result = calculateTotal(subtotal, order)

  // 金額の整合性チェック（独立した検証ロジックと突合）
  const expectedFinal = verifyAmount(subtotal, order)
  const diff = Math.abs(result.finalAmount - expectedFinal)
  if (diff > AMOUNT_TOLERANCE) {
    throw new Error(
      `金額不整合エラー: 期待値 ${expectedFinal.toLocaleString()}円 / 実際 ${result.finalAmount.toLocaleString()}円`
    )
  }

  await saveOrder(result)
  await sendOrderConfirmation(order.userId, result)

  return result
}

// 合計金額を計算する
function calculateTotal(subtotal: number, order: Order): OrderResult {
  const taxRate = getTaxRate(order.orderDate)
  const taxAmount = calculateTax(subtotal, taxRate)
  const totalWithTax = subtotal + taxAmount

  // ポイント値引き（税込金額から差し引く）
  const pointDiscount = calculatePointDiscount(totalWithTax, order.pointsUsed)
  const afterPoints = totalWithTax - pointDiscount

  // クーポン値引き（税込金額に対して割引率を適用）     ← コメントは「税込金額」
  const couponDiscount = calculateCouponDiscount(afterPoints, order.coupon)
  //                                             ^^^^^^^^^^
  //                        実際に渡しているのは afterPoints（ポイント差引後）
  //                        仕様では totalWithTax（税込金額全体）が正しい

  const finalAmount = afterPoints - couponDiscount

  return {
    orderId: order.orderId,
    subtotal, taxAmount, totalWithTax,
    pointDiscount, couponDiscount, finalAmount,
  }
}

// 検証用: 仕様どおりの計算で金額を算出する
// discount-service.ts の applyAllDiscounts に委譲
function verifyAmount(subtotal: number, order: Order): number {
  const taxRate = getTaxRate(order.orderDate)
  const taxAmount = calculateTax(subtotal, taxRate)
  const totalWithTax = subtotal + taxAmount

  const { finalAmount } = applyAllDiscounts(
    totalWithTax, order.pointsUsed, order.coupon
  )
  return finalAmount
}
input/src/discount-service.ts applyAllDiscounts が正しい適用順序を持つ 
// 割引処理モジュール
// ポイント利用とクーポン適用を扱う
//
// 仕様:
//   ポイント: 税込金額から差し引く（1ポイント = 1円）
//   クーポン: 税込金額に対して割引率を適用
//   併用時の適用順: クーポン → ポイント
//     （クーポンは税込金額全体に対する割引率、ポイントは固定額控除）

import { Coupon, DiscountBreakdown } from './types'
import { POINT_VALUE, MAX_COUPON_DISCOUNT_RATE } from './config'

// ポイント値引き額を計算する
export function calculatePointDiscount(
  amount: number, pointsUsed: number
): number {
  if (pointsUsed <= 0) return 0
  const pointValue = pointsUsed * POINT_VALUE
  return Math.min(pointValue, amount)
}

// クーポン値引き額を計算する
// クーポンは税込金額に対して割引率を適用する
export function calculateCouponDiscount(
  amountWithTax: number, coupon: Coupon | null
): number {
  if (!coupon) return 0
  if (amountWithTax < coupon.minOrderAmount) return 0
  const effectiveRate = Math.min(coupon.discountRate, MAX_COUPON_DISCOUNT_RATE)
  return Math.floor(amountWithTax * effectiveRate)
}

// 全割引を一括適用する（仕様準拠の適用順序）
// クーポン（税込金額全体ベース） → ポイント（固定額控除）の順
export function applyAllDiscounts(
  totalWithTax: number,
  pointsUsed: number,
  coupon: Coupon | null
): DiscountBreakdown {
  const couponDiscount = calculateCouponDiscount(totalWithTax, coupon)
  //                                             ^^^^^^^^^^^^
  //                     こちらは totalWithTax を渡している（正しい）
  const afterCoupon = totalWithTax - couponDiscount
  const pointDiscount = calculatePointDiscount(afterCoupon, pointsUsed)
  const finalAmount = afterCoupon - pointDiscount
  return { couponDiscount, pointDiscount, finalAmount }
}

// ポイントの残高チェック
export function validatePointBalance(
  availablePoints: number, requestedPoints: number
): boolean {
  return requestedPoints >= 0 && requestedPoints <= availablePoints
}

with-ai/prompt.md 
本番環境で金額不整合エラーが断続的に発生している。エラーログとソースコードから根本原因を特定し、修正コードを提示してほしい。

## 対象ファイル

エラーログ: input/error-log.txt（25件、正常注文と異常注文が混在）
ソースコード: input/src/ 配下の8ファイル（TypeScript、注文処理システム）

## 分析の進め方

Step 1 -- パターン抽出
エラーログ25件を全件読み、エラー注文だけに共通する条件を特定する。
「金額帯」「ユーザー」「商品」「日付」「ポイント利用」「クーポン適用」の
各軸で分類し、エラー有無との相関を洗い出す。

Step 2 -- 差額の法則性
エラー注文の差額（期待値と実際の差）に数値的な規則性がないか調べる。
差額を注文の各パラメータ（ポイント額、クーポン率、税込金額など）と照合し、
差額を説明できる数式を導出する。

Step 3 -- コード追跡
order-service.ts のprocessOrder内で「期待値」と「実際」がどう計算されて
いるかを追跡する。2つの計算パスの違いを特定し、Step 2で導出した差額の
法則性がコードの差異から数学的に導けることを証明する。

Step 4 -- 波及分析
直接のバグ箇所だけでなく、関連する問題がないか確認する。
discount-service.ts、config.ts、pricing-engine.ts に仕様との乖離や
未使用の定数がないかも調べる。

## 出力形式

1. ログ全件の分類表（条件別の件数とエラー有無）
2. 差額の法則性（数式で表現）
3. 根本原因（コードの具体的な行番号と、何が間違っているか）
4. 数式による証明（変数を使った一般化）
5. 検算（エラー注文1件を選び、正しい計算と誤った計算の双方を手順ごとに実行）
6. 単体テストで検出できなかった理由
7. 副次的な問題（あれば）
8. 修正コード
9. 再発防止の推奨事項
