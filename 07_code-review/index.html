Critical

XSS脆弱性 -- Stored XSS (CWE-79)

CartItemCard.tsx L36-39

{item.note && (
  <div
    className="cart-item-note"
    dangerouslySetInnerHTML={{ __html: item.note }}
  />
)}

ユーザー入力をサニタイズせずHTML描画。<img onerror="..."> でセッションCookie窃取が可能。

修正コードを見る 
// テキストとしてそのまま描画（推奨）
{item.note && (
  <p className="cart-item-note">{item.note}</p>
)}

// リッチテキストが必要なら DOMPurify
import DOMPurify from 'dompurify'
dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(item.note) }}
Critical

認証バイパス -- デバッグエンドポイント残留 (CWE-489)

cart-router.ts L37-40

router.get('/cart/debug', async (req, res) => {
  const allCarts = await prisma.cart.findMany({ include: { items: true } })
  res.json(allCarts)
})

認証なしで全ユーザーのカートを返却。全顧客の購買データが GET /cart/debug で漏洩する。

Critical

N+1クエリ -- ループ内商品個別取得 (CWE-400)

cart-service.ts L63-72

for (const item of cart.items) {
  const product = await prisma.product.findUnique({
    where: { id: item.productId },
  })
  // ... N商品 → N回SQL
}

カートの商品数に比例してSQLが増加。100商品で100回のDBラウンドトリップ。include で1回のJOINに集約すべき。

Critical

競合状態 -- Lost Update (CWE-362)

cart-service.ts L7-51

// read-then-write パターン（TOCTOU）
const cart = await prisma.cart.findFirst({ ... })       // SELECT
const existingItem = cart.items.find(...)                // アプリ側 find
await prisma.cartItem.update({ data: { quantity: existingItem.quantity + request.quantity } })
// ↑ 2タブ同時操作で片方の加算が消失する

トランザクション + quantity: { increment } のアトミック操作で解決。

# コードレビュー プロンプト

以下のdiffを本番リリース前のコードレビューとして精査してください。

対象ファイル: `./input/cart-feature.diff`

## レビュー観点（優先度順）

1. セキュリティ
   - XSS, SQLi, SSRF, 認証・認可の不備
   - ユーザー入力のバリデーション漏れ
   - デバッグ用コードや機密情報の残留
2. 並行性・データ整合性
   - 競合状態（TOCTOU, Lost Update）
   - トランザクション境界の妥当性
3. パフォーマンス
   - N+1クエリ、不要な再取得
   - メモリ使用量（上限なしの全件取得等）
4. 型安全性
   - any型の使用箇所と修正方法
   - null/undefined の未チェックアクセス
5. 保守性
   - デッドコード、命名、マジックナンバー

## 出力形式

各指摘を以下のフォーマットで出力:

- カテゴリ別にグループ化
- 重要度: Critical / Warning / Info
- CWE番号を付与（該当するものがあれば）
- ファイル名と行番号を明記
- 問題のコードを引用
- 攻撃シナリオまたは障害シナリオを具体的に記述
- 修正後のコードスニペットを提示
- 末尾に重要度別の検出件数サマリーテーブル
