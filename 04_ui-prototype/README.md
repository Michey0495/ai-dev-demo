# テーマ04: テキストワイヤーフレームからUIプロトタイプへの変換

## 概要

手書きやテキストで作成したワイヤーフレームを、AI Coding Agentに渡してブラウザで動作するUIプロトタイプに変換するデモ。
営業ダッシュボードを題材にして、レスポンシブ対応・アクセシビリティ・インタラクション・視覚的な洗練さの4点がどう変わるかを体験する。

## Before（AI未使用）

`before/dashboard.html` を直接ブラウザで開いてみてほしい。

目立つ問題点:
- 全体が width: 1200px の固定幅。画面を狭めるとコンテンツがはみ出す
- div の入れ子だけで構造化されていて、スクリーンリーダーが何も読み取れない
- style属性が全要素にべた書きされている。色やサイズの統一感がない
- 状態バッジが緑・オレンジ・グレーの3色で、絵文字まで入っている
- グラフエリアは「実装予定」のテキストだけ
- テーブルのヘッダーに th ではなく td を使っている

## After（AI活用）

`expected-output/dashboard.html` をブラウザで開いて、Beforeと見比べてほしい。

改善された点:
- Tailwind CSSによるユーティリティクラスで、見た目とHTML構造が分離されている
- モバイル / タブレット / デスクトップの3段階でレスポンシブに対応
- header, nav, main, aside, footer といったセマンティックHTMLに書き直されている
- aria-label属性でスクリーンリーダーへの配慮が入っている
- ネイビー+ウォームグレーの2系統に絞った配色で、落ち着いた印象に統一
- SVGで折れ線グラフを描画し、ホバーで各月の売上金額がツールチップ表示される
- ダークモード切替をヘッダーに配置。OS設定を初期値に反映
- テーブルの列ヘッダークリックで昇順/降順ソートが動作する（金額は数値ソート、日付はISO順）

## 手順

1. `input/wireframe.md` を開き、ASCIIワイヤーフレームの内容を確認する
2. `before/dashboard.html` をブラウザで開き、AI未使用版の問題点を把握する
3. `with-ai/prompt.md` のプロンプトテンプレートを読み、どう指示を構成するか学ぶ
4. 実際にAI Coding Agentへプロンプトを投げて、生成結果を確認する
5. `expected-output/dashboard.html` と見比べ、差分を分析する

## ファイル構成

```
04_ui-prototype/

  input/
    wireframe.md         ... ASCIIアートによるワイヤーフレーム定義
```

## 学習のポイント

ワイヤーフレームをAIに渡すとき、曖昧な指示では曖昧な結果しか返ってこない。
配色ルール、レスポンシブのブレイクポイント、アクセシビリティ要件を明示的に書くことが、実用レベルのアウトプットを引き出す分岐点になる。

プロンプトに「きれいにして」と書くのではなく、「ネイビー #1e3a5f とウォームグレー #6b7280 の2系統のみ」「768px以下でサイドバーを非表示」のように数値と具体を入れる。
この粒度の違いが、手戻りの回数を劇的に減らす。

今回のAfter版では見た目だけでなく、グラフのホバー表示・テーブルソート・ダークモードといったインタラクションも含まれている。プロンプトで動的機能の仕様を具体的に書けば、「見るだけのモックアップ」から「触って検証できるプロトタイプ」まで一気に到達できる。
