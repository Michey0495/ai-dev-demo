# テーマ06: 既存コードからのテスト自動生成

## 概要

実装済みのTypeScriptユーティリティに対して、AI Coding Agentで網羅的なテストスイートを一括生成するデモ。
日付計算ユーティリティを題材にして、人間が書いた最小限のテストとAI生成の包括的テストの差を体験する。

## Before（AI未使用）

`before/date-utils.test.ts` を開いてみてほしい。

目立つ問題点:
- 10関数のうち5関数しかテストされていない
- 各関数に対してハッピーパスが1件ずつだけ
- 境界値テストがゼロ: うるう年2月29日、月末、年度切り替わり
- 異常系テストがゼロ: null、undefined、不正な型への対処が未検証
- 営業日計算の肝である祝日・振替休日のテストが一切ない
- テスト件数は合計5件。カバレッジとしては体裁を整えた程度

実務でよくある「とりあえずテスト書いたが正常系だけ」という状態を再現している。

## After（AI活用）

`expected-output/date-utils.test.ts` と見比べてほしい。

改善された点:
- 全10関数に対してdescribeブロックが用意されている
- テストケースは80件。正常系・境界値・異常系を網羅
- うるう年の2月29日、平年の2月29日の両方を検証
- 会計年度の3月31日/4月1日の境界を明示的にテスト
- 金曜+1営業日=月曜、祝日チェーン、振替休日のスキップロジックをカバー
- null/undefined/不正な型に対するエラーハンドリングを検証
- 各テストが独立して実行可能で、テスト間の状態依存がない

## 手順

1. `input/date-utils.ts` を開き、10個の日付計算関数の実装を確認する
2. `before/date-utils.test.ts` を読み、テストの抜け漏れを自分で数えてみる
3. `with-ai/prompt.md` のプロンプトテンプレートを読み、AI向けの指示構成を学ぶ
4. 実際にAI Coding Agentへプロンプトを投げて、生成されるテストを確認する
5. `expected-output/date-utils.test.ts` と見比べ、カバレッジの差分を分析する

## ファイル構成

```
06_test-generation/
  README.md              ... このファイル
  input/
    date-utils.ts        ... テスト対象の日付計算ユーティリティ（10関数）
  before/
    date-utils.test.ts   ... AI未使用のテスト（5件、ハッピーパスのみ）
  with-ai/
    prompt.md            ... AI Coding Agent向けプロンプトテンプレート
  expected-output/
    date-utils.test.ts   ... AI活用で生成した包括的テストスイート（80件）
```

## 学習のポイント

テスト生成でAIが力を発揮するのは「網羅性」の部分。人間は正常系を書いたあと、境界値や異常系を列挙する作業を面倒に感じて後回しにしがち。AIはこの列挙作業を苦にしない。

一方で、プロンプトに「テストを書いて」とだけ言えば正常系ばかりが返ってくる。「境界値」「異常系」「営業日の祝日チェーン」のように観点を明示することが、実用的なテストを引き出す分岐点になる。
テスト件数を5倍に増やしたところでバグが5倍見つかるわけではないが、リグレッションを防ぐ安全網の密度は確実に上がる。特に日付計算のような「ほぼ正しいが特定条件で壊れる」タイプのロジックにはこの密度が効く。
