# リファクタリング用プロンプト

Claude Code で段階的に使う。1ステップずつ進め、各段階で動作確認してから次へ。

---

## Step 1: 分析（コード変更なし）

```
input/import-processor.ts を読んで分析してほしい。コードは変更しない。

確認したいこと:
- この関数が担っている責務を全部挙げる
- if-else の最深ネストは何段か
- マジックナンバーを全部列挙する（行番号付き）
- any が何箇所あるか
- テストを書こうとしたとき、何が障害になるか

出力は箇条書きで。
```

## Step 2: 型定義の抽出

```
分析結果を踏まえて expected-output/src/types.ts を作成してほしい。

定義する型:
- CSVから読み取った生データ1行（RawRecord）
- DB挿入形式のレコード（CustomerRecord）
- バリデーションエラーの詳細（ValidationError）
- インポート結果の集計（ImportSummary）
- 関数の戻り値（ImportResult）
- CSVパース結果（ParsedCSV）

条件:
- any は一切使わない
- readonly で不変性を保証する
- ReadonlyArray を配列型に使う
```

## Step 3: 定数の抽出

```
import-processor.ts のマジックナンバーを constants.ts に抽出してほしい。

対象:
- 50（名前の最大文字数）
- 10, 11（電話番号の桁数）
- 18, 120（年齢の下限・上限）
- 100, 999999（金額の下限・上限）
- 3（メールドメインの最小文字数）
- 必須ヘッダーのリスト
- 通知先メールアドレス
- メールの件名
- メール本文のテンプレート関数
```

## Step 4: CSVパーサーの分離

```
CSV読み込みとパースを csv-reader.ts に分離してほしい。

やること:
- ファイル読み込み（fs依存をここに閉じ込める）
- 1行パース（引用符対応）
- 必須ヘッダーの検証
- データ行をRawRecord配列に変換

ファイルパスを受け取り、ParsedCSV を返す。
ファイル不在やヘッダー不備は例外をスローする。
```

## Step 5: バリデーションの分離

```
バリデーションロジックを validator.ts に分離してほしい。

条件:
- Zod スキーマで宣言的に定義する
- 元のコードと同じバリデーション条件を維持する
- エラー時は「どのフィールドが」「なぜ」失敗したか返す
- 元のコードは最初のエラーで continue していたので、最初の1件だけ返す
- constants.ts の定数を参照する
```

## Step 6: 変換ロジックの分離

```
データ変換を transformer.ts に分離してほしい。

対象:
- 電話番号の正規化（記号除去 → ハイフン付きフォーマット）
- 年齢計算
- メールアドレスの小文字化とトリム
- 都道府県のトリム

すべて副作用なしの純粋関数にする。
入力は RawRecord、出力は CustomerRecord。
```

## Step 7: DB操作と重複チェックの分離

```
DB関連を2ファイルに分離してほしい。

duplicate-checker.ts:
- DatabaseClient インターフェースを定義する（DIできるように）
- メール or 電話番号で既存レコードを検索
- DB障害時は例外をスロー（握りつぶさない）

repository.ts:
- レコードをDBに挿入する
- 失敗時は例外をスロー
```

## Step 8: 通知の分離

```
通知ロジックを notifier.ts に分離してほしい。

- MailClient インターフェースを定義する
- constants.ts のテンプレート関数でメール本文を組み立てる
- エラーが0件なら何もしない
```

## Step 9: オーケストレータの書き直し

```
import-processor.ts を書き直して、上の全モジュールを組み合わせるオーケストレータにしてほしい。

条件:
- db と mailer を引数で受け取る（テスト時にモック注入できるように）
- ビジネスロジックをこのファイルに書かない
- 処理フローだけを記述する
- エラーハンドリングは適切に行う
```

## Step 10: テストの作成

```
import-processor.test.ts を作成してほしい。vitest を使う。

カバーするケース:
- 正常系: 有効レコード1件、複数件、データ正規化の検証
- バリデーション: 名前空、メール不正、電話番号桁数不足、金額範囲外、年齢制限
- 重複: スキップされること
- DBエラー: 重複チェック障害、挿入障害
- 通知: エラー時に送信、エラーなしなら未送信、送信失敗でもインポート結果に影響しない
- 複合: 有効・無効・重複が混在するCSVの集計
- パースエラー: readCSV の例外が伝搬すること

csv-reader はモック化してファイルIOを排除する。
db と mailer はインターフェースに準拠したモックを注入する。
```
