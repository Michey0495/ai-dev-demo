# テーマ10: リファクタリング -- モノリシック関数を分解する

## 概要

200行のモノリシック関数を、型付き・テスト可能・責務分離されたコードへ段階的にリファクタリングする。
対象は CSV インポート処理。ファイル読み込みからDB保存、通知送信まで1関数に詰め込まれた典型的なレガシーコードを題材にする。

## 題材コードの問題点

input/import-processor.ts に含まれる processCSVImport 関数が抱えている問題:

- 7段ネストの if-else（メールアドレスのバリデーション周辺が最深）
- 20以上の分岐パス
- マジックナンバー散在（50, 10, 11, 18, 120, 100, 999999, 3）
- 型定義なし（any と暗黙の any が大量）
- CSVパースロジックをヘッダー行とデータ行で2回コピペ
- 年齢計算をバリデーションとデータ変換で2回コピペ
- IO・バリデーション・変換・永続化・通知が1関数に混在
- メールテンプレートのハードコード
- エラーハンドリングが console.log のみ
- 変数名が1文字（s, f, sk, q, c, tmp, rec）

## フォルダ構成

```
10_refactoring/
  input/
    import-processor.ts      -- 200行スパゲティ（リファクタリング対象）
  before/
    import-processor-v2.ts   -- 途中で壊れたリファクタリング（失敗例）
  expected-output/
    src/
      types.ts               -- 型定義（any排除・readonly）
      constants.ts           -- マジックナンバーの定数化
      csv-reader.ts          -- ファイル読み込みとパース
      validator.ts           -- Zodスキーマによるバリデーション
      transformer.ts         -- データ正規化・変換（純粋関数）
      duplicate-checker.ts   -- 重複検出（DI対応）
      repository.ts          -- DB操作
      notifier.ts            -- 通知送信
      import-processor.ts    -- オーケストレータ（ロジックなし）
      import-processor.test.ts -- vitest による振る舞い保持テスト
  with-ai/
    prompt.md                -- Claude Code用の段階的プロンプト
```

## Before / After

### input/（スパゲティ版）

1関数200行。CSV読み込み、パース、バリデーション、変換、重複チェック、DB挿入、通知送信、集計をすべて担う。
テストを書こうにもDB・ファイルシステム・メール送信に直接依存しており、モック化が困難。
CSVパースと年齢計算が2箇所にコピペされている。

### before/（壊れたリファクタリング）

誰かが途中までリファクタリングを試みた版。関数の切り出しは始めたが、3つの致命的バグを埋め込んだ。

1. validateRecord が boolean しか返さない -- エラー詳細が消えた
2. checkDuplicate がDB障害時に false を返す -- 不正データが挿入される
3. errors.push の漏れ -- 重複スキップとDB挿入失敗が通知メールに載らない

この「中途半端なリファクタリング」自体がよくある失敗パターンの教材になる。

### expected-output/（完成形）

10ファイルに分離。各ファイルが単一責務を持つ。db と mailer を引数で受け取る設計にしたことで、テスト時にモック注入できる。

## リファクタリング手順

1. 型定義を抽出する -- any を排除し、データの形を明示する
2. マジックナンバーを定数化する -- 意味のある名前を与える
3. CSV読み込み・パースを分離する -- IO関心事を隔離する
4. バリデーションを抽出する -- Zodスキーマに置き換える
5. 変換ロジックを抽出する -- 電話番号正規化、年齢計算を独立させる
6. 重複チェックを分離する -- DBへの問い合わせを単独の関数にする
7. DB操作をRepositoryとして切り出す -- 永続化の関心事を閉じ込める
8. 通知送信を分離する -- メールテンプレートとともに独立させる
9. オーケストレータを書く -- 上記を組み合わせるだけの薄い関数にする
10. テストを書く -- 各モジュールをモック化し、振る舞い保持を確認する

## AI活用のポイント

with-ai/prompt.md にプロンプトテンプレートを用意している。
Claude Code に元のコードを読み込ませ、1ステップずつリファクタリングを依頼する流れで使う。

一度に全部やらせると、元の振る舞いが変わってしまうリスクがある。
1ステップずつ進め、各段階で動作確認しながら進めるのが鉄則。
