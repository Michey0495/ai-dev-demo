# 05 CRUD実装 -- API仕様とPrismaスキーマから完全なCRUDルーターを生成する

## テーマ概要

ブログ記事APIの仕様書とPrismaスキーマを入力に、Express + Zodで完全なCRUDルーターを生成するデモ。
人間がスケルトンから埋めていく従来の方法と、AIが仕様+スキーマから一発生成する方法を比較する。

テーマが「API設計」ではなく「実装」に絞っている点が03_api-designとの違い。
設計は済んでいる前提で、そこからどれだけ速く正しいコードに落とせるかを見せる。

## 所要時間

15分

## フォルダ構成

```
05_crud-implementation/
  input/
    api-spec.md              -- ブログ記事APIの仕様書
    schema.prisma            -- Post/Author/Tagモデルを定義したPrismaスキーマ
  before/
    routes.ts                -- ルート定義だけのスケルトン（ハンドラ未実装）
  with-ai/
    prompt.md                -- Claude Codeに渡すプロンプト
  expected-output/
    routes.ts                -- Zod検証+Prismaクエリ+エラー処理を含む完全実装
```

## Before（人間がスケルトンから始めた場合）

before/routes.ts の状態:

- 5つのルート定義だけが存在し、ハンドラ本体はすべてTODOコメント
- バリデーションの仕組みが未導入
- ページネーションの方針が未定
- エラーハンドリングのパターンが統一されていない
- slugの自動生成ロジックがない
- タグのリレーション操作がどうなるか見えていない

ここから1エンドポイントずつ埋めていくと、5つ分で30分から1時間は必要になる。

## After（AIで生成した場合）

expected-output/routes.ts の特徴:

- Zodスキーマによるリクエスト検証（タイトル100文字制限、必須フィールドなど）
- カーソルベースのページネーション
- status/tagでのフィルタリング
- slugの自動生成（タイトルからケバブケースに変換、重複時はサフィックス付与）
- Prismaのリレーション操作（connectOrCreate）によるタグ管理
- 400/404/409/500を適切に使い分けるエラーレスポンス
- TypeScriptの型が全体に通っている

## デモ手順

1. input/api-spec.md とinput/schema.prisma を開き、ゴール像を把握する（2分）
2. before/routes.ts を見せ、ここからどう実装するか参加者に聞く（2分）
3. with-ai/prompt.md のプロンプトをClaude Codeに渡して生成する（3分）
4. 生成されたコードを expected-output/routes.ts と並べて比較する（5分）
5. Zodスキーマ、ページネーション、slug生成など個別のポイントを解説する（3分）

## 学びのポイント

- 仕様書+DBスキーマという2つのコンテキストを同時に食わせると、整合性の取れたコードが出る
- Zodバリデーションの定義は仕様書の制約をそのまま写像する作業。AIが得意な領域
- カーソルベースページネーションのようなベストプラクティスを知らなくても、仕様に書いておけばAIが正しく実装する
- タグのconnectOrCreateパターンなど、Prisma固有の書き方もAIが適切に選択する
- beforeのスケルトンは「構造を考える」時間であり、AIを使えばその時間を設計レビューに回せる
